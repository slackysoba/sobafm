# Roadmap

The [Project board](https://github.com/users/slackysoba/projects/3) tracks the work; linked issues record scope, dependencies and acceptance evidence. Detail the current and next slice; later outcomes stay concise.

| Outcome | Exit |
| --- | --- |
| [1. Source and feasibility](https://github.com/slackysoba/sobafm/issues/1) | A bounded music-quality comparison and one feasible Linux deployment/resource design |
| [2. Existing music end to end](https://github.com/slackysoba/sobafm/issues/2) | Eligible music plays in Discord from the intended container, with correct credits, stop and cleanup; then continuous selection, skip and replacement |
| [3. Generated music in one station](https://github.com/slackysoba/sobafm/issues/3) | Validated interpretation, generated continuity/duration and safe mode changes |
| [4. Operator-ready deployment](https://github.com/slackysoba/sobafm/issues/4) | Persistent settings/channel, permissions, recovery, documentation and both Linux architectures |
| [5. Qualified release](https://github.com/slackysoba/sobafm/issues/5) | Actual quality acceptance, latency/endurance, memory/release evidence and a clean Linux/Docker BOTH-mode walkthrough |

Statuses: Backlog, Ready, In progress, In review, Blocked, Done. Ready means bounded scope, acceptance criteria and satisfied prerequisites. Blocked names a real missing dependency or decision. Done requires evidence.

Initial Ready tasks are [source evaluation](https://github.com/slackysoba/sobafm/issues/6), [Linux feasibility](https://github.com/slackysoba/sobafm/issues/7) and the [minimal development/CI foundation](https://github.com/slackysoba/sobafm/issues/8). All belong to Outcome 1. Outcomes 2–5 depend in order on their predecessor; the Project uses native parent/dependency links and repository milestones. Each outcome requires evidence from the implementation and release under review.
