# Decision records

Add short records for consequential product, architecture, service, cost, security or legal choices.

Each record states the problem, realistic options, decision/status, reasons, consequences and verification needed. Link its issue. Do not write an ADR for routine implementation choices.

An accepted decision is superseded by a new record rather than edited in place. Initial decisions concern catalog selection/storage and a feasible Linux resource configuration. Proposed records are not accepted until the required decision and evidence are recorded.
