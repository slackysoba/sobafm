# Architecture

The offline catalog selector, the pure station-fact and credit-rendering logic, the PCM banks, the first-slice decode producer and the Discord adapter for the first playback slice are implemented. `python -m sobafm` connects them with a startup limit gate, and a Dockerfile and Compose service package the result ([operations](operations.md)). None of it has been built as an image, run under its limits or tested live. The Docker resource model for the first amd64 playback slice is [accepted](decisions/0004-amd64-whole-service-adoption.md) but not yet qualified. The rest of the station, playback and deployment architecture below remains proposed and unqualified.

SobaFM has one station/player per server. Commands validate access and intent. A mode-specific interpreter produces a validated musical plan. Catalog selection or generated production prepares audio; the connected player settles what listeners actually hear. Settings and remembered channels persist in SQLite.

Catalog preparation happens ahead of playback: source admission, provenance, credits, curation and descriptors. Runtime selection ranks eligible candidates and retrieves audio according to source policy. Start small; add adapters or audio analysis only when useful.

## Implemented catalog boundary

`catalog.py` validates bounded prepared metadata and separate trusted admission reviews, and `eligible` returns the admitted recordings from every supplied partition. Reviews bind complete credits and access readiness to an immutable recording digest. Unreviewed, changed, unavailable or incomplete recordings remain rejected. No provider or model approval field is accepted in recording metadata. Each recording may carry `details`, source text such as tags, tempo and album kept as matching hints. They stay outside the digest, so enriching them leaves reviews valid.

`gemini_interactions.py` makes one bounded call to the Gemini Interactions API ([ADR 0006](decisions/0006-gemini-play-matching.md)). A `GeminiClient` holds the API key, the transport and the limit on calls in flight. Calls have `store` off, a response schema, a 10-second timeout, a 64,000-byte response limit and no retries. At most four run at once per client, and one client serves all servers: a request body is built only once its call holds a slot, and waiting for one counts toward the same 10 seconds. After `close` the transport refuses further calls, so a request arriving during shutdown can't open a new session. Failures raise `GeminiFailed` with a safe kind. `AiohttpTransport` uses the `aiohttp` already in the lock, follows no redirects and creates its session on first use.

`gemini_match.py` turns a `/play` request into a plan with one such call. `GeminiMatcher` owns the service's client and prepares a compact description of the admitted recordings once at startup, refusing one over 512,000 characters. Each call sends that list and the JSON-encoded request. `parse_plan` rejects the whole output unless it is exactly the expected shape and names only distinct positions in the list, so the model can only choose an admitted recording. The result is `Matched` (up to 20 recordings, best first, each with a fit of exact, close or loose) or `Refused`, and failures raise `MatchFailed`, its name for `GeminiFailed`. Only the kind, outcome, count and duration are logged.

`catalog_import.py` converts bounded saved Jamendo tracks responses, ccMixter info responses and explicit FMA operator manifests into the same validated snapshot schema. Source-specific field maps preserve identity, credit evidence and unknowns. A separate report records malformed rows, missing requested IDs and bounded source coverage; conflicting duplicate identities are quarantined together. Outputs contain no media URLs or generated admission decisions. The importer's draft metadata still needs complete-kind/access evidence and separate credit review before selection admission. See [saved metadata imports](catalog-evaluation.md#saved-source-metadata-imports).

`catalog_prepare.py` and `media_check.py` apply the batch rule in [ADR 0007](decisions/0007-fma-dataset-batch-catalog.md) at ingestion. `catalog_prepare.py` decides which FMA dataset listings qualify and in what order, turns a listing into the importer's manifest form, marks validated recordings complete and available, and writes the media manifest and the reviews. `media_check.py` decodes a file through the real `DecodeProducer`, screens the decoded audio for long silence and sustained clipping without keeping it, and reads its ID3 tags. Neither makes a network request or uses a model, and the running service imports neither. The two scripts under `evaluations/catalog/` drive them: `fma_fetch.py` makes the requests, through one metered client with stop conditions, and `fma_build.py` runs the offline stages.

Partition completeness describes only the dated prepared subset. `catalog.py`, `catalog_import.py` and `catalog_prepare.py` perform no provider calls, audio access, state changes or Discord operations. See the [catalog contract](catalog-evaluation.md#current-selection-contract) and accepted decisions [0002](decisions/0002-prompt-catalog-selection.md) and [0006](decisions/0006-gemini-play-matching.md).

The audio callback consumes prepared PCM without blocking. Producers and cleanup retain explicit ownership across cancellation. Capacity admission includes retained work and cleanup debt. Prove the chosen Linux enforcement configuration before depending on it throughout the application.

## Generated-plan interpretation (not yet wired in)

`freestyle_plan.py` turns a `/freestyle` request into a validated generated plan with one call through `gemini_interactions.py`. It is a library module: nothing registers `/freestyle` or calls it from Discord yet, and no transport reads its plans. When it is wired in, it should use the matcher's `client`, so one limit on calls in flight covers both modes, or its own client when no catalog is configured.

`PlanInterpreter.interpret(request, current)` has three outcomes, each its own type:

- `Planned` holds a `GeneratedPlan`: a title of at most 60 characters, one to four distinct styles of at most 100 characters with weights from 0.1 to 1.0, and optional tempo (60 to 200 BPM), key (twelve scales), density and brightness (0 to 1), `mute_drums` and `wordless_vocals`. These follow [Lyria RealTime's guide](https://aistudio.google.com/docs/realtime-music-generation) and [API reference](https://aistudio.google.com/api-reference/live-music), checked on 2026-11-05. The plan uses plain values and no transport types. Lyria normalizes weights and doesn't take zero, so the plan's weight range is a positive part of what Lyria accepts.
- `PlanRefused` means the model judged the text unrelated to music, a prompt-injection attempt or disallowed. Current music must not change.
- `PlanFallback` means interpretation failed: a timeout, a provider or transport error, or output that isn't exactly the expected shape. The checked request becomes the only style, under a fixed title and with every control left to the generator. Its type is the flag for disclosure, and `failure` holds the safe kind.

Output naming the refuse outcome is a refusal whatever else it holds, because treating it as a failure would send text the model declined to the generator. Text failing `checked_request` raises `CatalogInputError` with no call or fallback, and cancellation propagates, so a fallback never starts music for a request nobody is waiting on. A call that fails has no verdict, so hostile text that also makes the call fail reaches Lyria as a direction, where it meets [Lyria's own safety filter](https://aistudio.google.com/docs/realtime-music-generation#limitations) and has no tools to reach. The same applies to an artist's name, which only a successful call can translate into musical characteristics.

The prompt holds the fixed instruction, the JSON-encoded request and, for a relative request, `current`: the generated plan now playing, as JSON. The signature accepts nothing else, so no Discord identity can reach it and the API key stays in a request header. A catalog program can't be `current`, so switching modes starts a fresh interpretation. The instruction asks for descriptive characteristics in place of artist names and for no lyrics, and the plan has no field that could carry lyrics. Whether the model follows that instruction is a question for the [opt-in evaluation](../evaluations/gemini_matching/README.md), which hasn't been run. Only the kind, outcome, style count and duration are logged, never titles or styles, and a title must be escaped before it is shown.

The guide calls the model instrumental only and also documents a `VOCALIZATION` mode that adds vocalizations "as another instrument". It doesn't mention words, so whether `wordless_vocals` output stays wordless needs a live check. The guide also says a new `bpm` or scale takes effect only after a context reset, which matters to whatever applies these plans. Offline tests use local fakes and establish validation, failure handling and the request's contents. They don't establish that the live API accepts this schema or that plans sound like their requests.

## Implemented PCM boundary

`pcm.py` fixes the playback format in one place: stereo signed 16-bit at 48 kHz, 192,000 bytes per second and 3,840-byte 20 ms frames. `GLOBAL_PCM_BANKS` is the process-wide owner of the two 2,304,000-byte banks that make up the accepted 4,608,000-byte PCM reservation ([ADR 0004](decisions/0004-amd64-whole-service-adoption.md)). It grants a lease before allocating a bank's backing and refuses when both leases are held, so nothing is allocated for a refused request. A lease stays charged until `release()` actually frees the backing. Release is refused while a producer region or any view of the backing still exists; cancellation only records its first monotonic time and stops the stream, and repeated cancellation changes nothing. The pool adds no capacity, baseline subtraction or other partition.

Each bank is a single-producer, single-consumer ring. The producer borrows a contiguous free region (suitable for a pipe `readinto`), fills it outside the bank lock and commits the filled prefix. It must settle every borrow with `commit_write`, using `commit_write(0)` on error, even if it already released the region view. `write()` is a copying convenience. The voice callback's `read_frame()` takes the bank lock without waiting and copies at most one 3,840-byte frame. It returns `None` when no frame is available now (not ready, underrun or a brief contended operation) and `b""` once no frame will follow. `ready_now()` reads the monotonic readiness flag without the lock, so the callback can tell an underrun from a stream that is not yet ready. Frames are readable only after readiness: 1,152,000 buffered bytes (six seconds), or the producer's verified end of a shorter valid stream. A decoder's output length need not be a multiple of the frame. At the verified end, a stream that is a whole number of 4-byte stereo samples and holds at least one whole frame is valid PCM; its remainder, shorter than one frame, is not emitted, and audible drain follows the last whole frame. A length that is not a whole number of samples means truncated output and fails as `partial_final_frame`; a nonzero stream shorter than one whole frame has nothing to emit and fails as `empty_pcm`, as does an empty one. Partial bytes are never emitted or padded with silence.

Transfer completion and decoder completion are recorded by their owners. Valid PCM comes from the verified end-of-PCM check. Audible drain means every whole frame of an ended, admitted stream has been handed to the voice callback. Each fact is tracked separately and none implies another. The module has no Discord library, decoder process, station logic, threads or dependency. `wait_writable()` lets a producer wait for free space without polling; the voice callback's frame reads notify it and never block. The decode producer below supplies the first completion policy and cleanup owner; voice integration belongs to a later slice. The 3,840-byte frame copy returned to the callback is application audio copy payload under the separate copy reservation; this module does not account for it. Offline tests do not qualify voice timing, Linux containment or useful fit.

## Implemented decode producer

`decode.py` is the first-slice producer for one admitted recording. A `DecodeInput` names the local file, its exact size and SHA-256, and a finite PCM output limit chosen by the caller; the limit is an overrun bound, not a duration oracle. One `DecodeProducer` owns the input file, one stock mpg123 child in its own process group, the child's stdin/stdout pipes, a feeder thread, a reader thread and one `GLOBAL_PCM_BANKS` lease. A caller that already holds a lease can pass that bank instead: the producer fills it at the same point in the launch, never acquires, keeps the bank's earlier first cancellation as its original clock, and leaves release of the lease to the caller.

Launch follows the [ADR 0004](decisions/0004-amd64-whole-service-adoption.md) premises. The decoder is started with `subprocess.Popen` (pipes, no PTY, stderr discarded, closed descriptors, a fixed minimal environment) before this producer leases PCM or starts a thread. `Popen` returns only after exec, so a forked child image is gone before any input; any bank it could have inherited was already leased and charged. The reviewed per-decoder limits (core 0, stack 524,288, data 12,000,000 and address space 12,524,288 bytes) are applied with `prlimit` after exec and before the first input byte. The argv is the one the #44 evaluation established: stereo signed 16-bit at 48 kHz on stdout, input on stdin, `--no-resync`. A test pins it to that established value.

The feeder streams the file through a fixed 16,384-byte chunk, checking size and hash, and closes stdin only at exact verified EOF. A truncated, oversized, unreadable or mismatched input never gives the decoder end of input: stdin stays open until the child is reaped. The reader fills the bank through `reserve_write`/`commit_write` and waits on `wait_writable()` when the bank is full. Output beyond the limit is an overrun. Transfer completion, decoder completion (exit status zero without cancellation, because mpg123 also exits zero on SIGTERM) and valid PCM are recorded separately in the bank and the `DecodeReport`. The verified end of PCM is declared only after a complete transfer, exit status zero and no failure, so a nonzero exit after full output and an overrun fail. The bank then applies the length rule above: sample-aligned output ending inside a frame is valid and every whole frame stays readable after `finish()` returns, while output that is not a whole number of samples or holds no whole frame fails. Any failure stops the bank's stream. Consumers only read frames from the bank and stop a decode through `DecodeProducer.cancel()`, not by cancelling the bank directly.

`finish()` is the single cleanup owner. The original deadline is three seconds after the first of cancellation, a failure or the decoder's end of output; repeated cancellation does not reset it. Cancellation or failure sends SIGTERM to the group at once and SIGKILL two seconds in. Once the stream stops, the reader closes the decoder's stdout, so a decoder blocked writing to a full pipe gets EPIPE and acts on SIGTERM instead of waiting for SIGKILL. If the bank's owner stopped the stream before calling `cancel()`, the reader first adopts that cancellation, with the owner's original time, so the decoder's exit and any failed input write count as cancellation; a decoder that ends its output but does not exit within one second is a stalled failure. The leader's exit is observed through a pidfd, the group is swept with SIGKILL while the unreaped leader pins its ID, and then the leader is reaped. Threads are joined and descriptors closed only after that. If a feeder or reader thread cannot start, that is a `thread_start` failure, and only the threads that did start are owned and joined. Settlement after the deadline is an `expired` verdict that a later release never changes. `release()` returns the bank lease only after the process, threads and descriptors have actually settled, and only when the caller no longer needs the bank.

The input chunk is application audio/IPC copy payload under the separate copy reservation, which this module does not account for. Tests use small Python children in place of mpg123. They do not qualify native mpg123 behavior, the limits under the real image, or fit under the group limit, which is a later local step.

## Implemented station facts and credits

`station.py` keeps one server's desired program, prepared audio, claimed switch and heard source as separate facts in a single-owner `Station`. Each accepted request gets an increasing generation and reports the unheard program whose work the caller must cancel. Preparation results, failures and switch reports carry their program or claimed audio; anything for a superseded program is returned as stale and changes nothing. Prepared audio is recorded only after its credits render. The player claims ready audio and then reports an actual switch or failure; only the switch changes the heard source. A failed, rejected or cancelled replacement reverts the desired program to the one still heard and leaves its credits unchanged. Stop ends the desired program, recording why when it ended without a command (an expired listener grace period); the heard source clears only when the player reports silence. A program carries the ranked recordings that `/play` obtained from one validated interpretation, and continues: after its first track is heard, `continue_program` opens the next track's preparation, `exhausted` records that none can follow (the program then ends when its heard track reports `drained`, with `ended` giving the reason until a new request or stop), and a failed next track keeps the program rather than reverting it. Each program has a bounded no-repeat history of every recording it prepared or tried, including credit-rejected ones; its size, 768, is the most recordings a valid snapshot can hold, so history is never cleared or evicted to repeat a track. Continuation facts are kept only for programs still desired, heard or holding audio, so a failed replacement restores the heard program's history and ending. `select_next(plan, history)` chooses each track: the best-ranked recording in the program's plan that its history doesn't hold. The module holds no audio, tasks, threads, persistence or clock, and has no member queue, replacement scheduling, generated mode or settings.

`credits.py` renders a recording's existing `catalog.py` credit snapshot: title, creators, source backlink, license and every notice. Provider text has bidirectional controls stripped, other control and line/paragraph separators replaced by spaces, and Discord markdown, mention, emoji and autolink characters backslash-escaped. Links are rendered only after the catalog's credential-free HTTPS validation plus an RFC 3986 character check, inside angle brackets. Pages are filled continuously up to 1,968 UTF-16 code units plus a footer, within Discord's 2,000-unit message limit; credits needing more than 16 pages raise `CreditRejected`, and the station treats that as a rejected candidate rather than truncating notices. Each page states that mentions are disallowed and previews suppressed for the Discord layer. `CreditViews` retains at most 256 caller-bound views, each expiring a fixed time after opening (600 seconds by default, at most 900) under injected monotonic time; when full it evicts expired then oldest views. Wrong-caller, unknown/expired and out-of-range requests receive refusals without page content.

## Implemented Discord adapter

`discord_adapter.py` registers `/join`, `/play request:<text>` (1 to 200 characters), `/skip`, `/now`, `/stop` and `/leave` with an `InteractionBot` that requests exactly the Guilds and Voice States intents. Commands are registered for the server context only and also refuse a missing server at runtime. `/join` and `/leave` carry Manage Server as their default member permission, so administrators customize access through Discord command permissions rather than a second role system. `/play`, `/skip` and `/stop` require the caller to be in the bot's voice channel; `/stop` also accepts a caller with Manage Server from elsewhere. `/now` has no extra requirement. Without a joined voice connection, `/play`, `/skip` and `/stop` explain that a manager must use `/join`. `/now` answers at once; the other commands defer before any voice, selection or cleanup wait, all ephemerally and with mentions disabled. If the deferral of `/stop` or `/leave` fails, whether Discord rejects it or the request does not complete, the command still silences (and `/leave` disconnects), sends no follow-up and logs the command name, the interaction's age and Discord's status and code or else the exception type, never its token.

`/play` defers, then asks the injected `Matcher` for a plan. A refusal or `MatchFailed` changes nothing and says so. One request is matched at a time per server; another during that wait is refused without a call. A `/stop`, `/leave` or shutdown during the wait wins, so the plan is then dropped. Otherwise the plan becomes a new `station.py` program carrying the ranked recordings, starting with the first whose credits render, and the reply states its fit using fixed wording and escaped catalog text. The adapter then claims the audio, leases a `pcm.py` bank from `GLOBAL_PCM_BANKS` and starts the injected `Producer` on the event loop. A refused lease reports a failed switch, leaving current audio heard. Only one unheard track is pending per server: a newer request displaces it, reports its switch as failed and joins its retirement (bounded by five seconds) before leasing again. Responses say the request is accepted and preparing, never that it is audible.

`StationSource` is the voice callback. It takes its lock without waiting and copies at most one frame from the pending or current bank. It switches when the pending bank yields its first frame, which `pcm.py` allows only after readiness. Before that, and during an underrun, it returns a silent frame so the player keeps its timing; it never pads a partial final frame. Under the same non-blocking lock it counts, as plain integers on the track, the whole frames it handed to the voice player and the silence frames it returned while the track was current, or pending and ready (underruns, which include a frame skipped because the bank's lock was momentarily held). These are frames handed to the player, not packets confirmed delivered. Switch, failed, drained and retired reports go to the event loop with `call_soon_threadsafe`. Only the switched report changes the heard source, so `/now` keeps the heard title and full credits until then, across every track boundary, and states when a newer request is starting. `/now` sends a status line followed by every rendered credit page as private follow-ups, with previews suppressed. When nothing is current or pending, the source returns end of stream and the player stops; the next claim restarts it.

A pending track is either a cut, which switches at its first ready frame (a new program's first track, or `/skip`), or a continuation, which the callback reads only once the current track has drained: in the same callback that finds the current track's end it emits the continuation's first frame, so catalog tracks play successively with no fade, overlap, looping or editing. When a program's track is heard, the adapter starts one continuation task for the server, recording which program it serves. A task still running for a superseded program, for example one waiting for capacity, is not reused: the newly desired program gets its own task, and the old one stays owned until it exits through its stale check. Under the player lock and only if the program is still desired and has no next track, it checks the pool: a retiring track still holds its bank and is counted there, so the continuation never waits on retirements themselves, and a stuck retirement elsewhere does not delay it while a bank is free. With a free bank it takes the next recording from the program's plan and history (at most three credit-rejected candidates per preparation), claims the audio and leases that bank. So at most the audible track and one prepared next track hold banks, within the unchanged two-bank capacity. Because the two banks are process-wide, another server's playback can hold the capacity a program needs. Without a free bank the continuation waits, consuming no attempt, until a retirement settles, a callback report arrives or shutdown begins, each of which wakes every waiting continuation, or until a timeout; it rechecks then, so there is no polling loop. While the program's own track is audible the wait lasts until that track ends, which frees its bank, rechecking at least every ten seconds; once the program has nothing audible, it waits at most `CAPACITY_WAIT_SECONDS` (ten seconds, past the three-second cleanup deadline of the drained track). So two servers each playing a track both continue, each after its own track ends and a gap. A program left silent by its drained track has priority for a freed bank over another server's program that is still audible, so a server still playing cannot starve one whose track has ended. A failed lease, a voice error or a next track whose decode fails leads to another attempt, at most three per heard track. When the attempts or the capacity wait are exhausted, or the plan has no recording left, the station records the reason and the program ends after the heard track drains, or at once if nothing is heard, with no hot loop and no history clearing; `/now` then gives the reason. A continuation whose decode fails is noticed when the callback reaches it, so a gap of silence can precede the next attempt. A pending `/skip` stays requested until its next track is handed to the voice player, so a failed start does not turn it into a natural continuation. At shutdown a waiting continuation returns at once; shutdown still joins every retirement under its existing rules.

`/skip` is registered only with a catalog and requires the caller in the bot's voice channel. It applies only while the desired program is the one heard. It marks a prepared or still-preparing next track as a cut, or asks the continuation task for one and waits up to five seconds for it; it never interprets the request again or queues anything. The current audio keeps playing until the next track is ready, and keeps playing if the next track fails. With no recording left, it says so. A `/play`, `/stop`, `/leave`, a lost voice connection settled at the next `/join` or `/leave`, or shutdown removes a prepared next track from the callback and retires it through the same path as any other track; a continuation task for a superseded program, and any late report for a removed track, change nothing.

A program ends `LISTENER_GRACE_SECONDS` (60) after the last listener leaves. A listener is a member in the bot's voice channel who is neither a bot nor deafened (`deaf` or `self_deaf`). With only the Guilds and Voice States intents, disnake's voice states are complete: `GUILD_CREATE` and every `VOICE_STATE_UPDATE` keep `Guild._voice_states`, including both deafened flags. Its member cache is not: without the members intent, members from `GUILD_CREATE` are not cached, and a member is added only by a voice state update while in voice, so `VoiceChannel.members` omits members already in voice when the bot connected. The adapter therefore counts `channel.voice_states`, skips its own user and reads the bot flag from the cached member; an uncached member counts as a listener, so the bot never cuts off a real listener, at the cost of continuing for an unseen bot until that bot changes voice state. The bot registers `on_voice_state_update` and re-evaluates the server on each update, after `/play` and after a `/join` move. With a desired program (playing or preparing) and no listener, it arms one grace period per server, bound to that program; a listener's return or undeafening cancels it, and a further change while armed does not restart it. A newer program cancels it and arms its own if still no listener remains. Every report that can change the desired program also reviews the server again: a failed switch (which can revert a replacement to the heard program), a failed start of ready audio, a drain and a continuation that ends its program. `/stop`, `/leave` and shutdown cancel it through the shared silence path, and SobaFM's own voice state leaving the channel cancels it. The timer is an adapter-owned task, so shutdown cancels and joins it, and its sleep is injected so tests control the clock. On expiry it takes the player lock and ends the program only if it is still the registered timer, the same program is desired, the player is connected and current and no listener has returned. If the desired program changed or a listener is present, it reviews the server again instead, so a program that became desired without a review (a failed replacement reverting to the heard program) gets its own grace period. Otherwise it silences through the `/stop` path with the `no_listeners` reason. Its tracks retire through the usual retirements with their original cleanup clocks, failed verdicts and debt, and the bot stays connected.

Every retired, displaced, failed or stopped track keeps its bank and producer task in one retirement task: cancel the bank, cancel and join the producer, then release. The cleanup deadline is three seconds from the bank's first recorded cancellation; a later cancellation does not reset it. A producer that settles after the deadline is a failed cleanup verdict, logged and counted, and the retirement keeps joining it and holds the bank until it settles. A bank that cannot yet be released stays leased in the adapter's debt list. `/stop` removes all audio from the callback, reports silence and waits up to five seconds for retirements before replying; ownership continues after that. `/leave` also disconnects. If the voice player cannot start, the claimed track is reported as a failed switch and retired.

SIGTERM and SIGINT set a stop event. From then on `/join` and `/play` are refused, a connection completed during shutdown is dropped, and no new bank is leased. `run` repeatedly disconnects every server and waits for all retirements until none remain, yielding to the event loop on every pass so a finished retirement's bookkeeping callback can run, retries release of retained banks and closes the client. It exits 0 only when no bank is retained, the pool reports no remaining lease and no cleanup deadline was missed.

The adapter logs what was played at INFO, under the requirements' logging rule and never with request text, tokens or interaction data: the recording key and credit snapshot ID when the heard source changes (and when it clears); for each settled retirement, taken before release, the frames handed to the voice player, underruns, `transfer_complete`, `decoder_complete`, `pcm_valid`, `audible_drain`, the bank's `failure`, whether the bank was released and the seconds from its first cancellation to release; voice connected and disconnected; and the shutdown outcome with the leases still held. A silence frame returned while the source's own lock is contended is not attributed to a track.

A voice connection lost outside the adapter is detected only when a command next runs: playback commands then report that the bot has not joined, and the lost player's tracks are retired at the next `/join` or `/leave`.

Configuration comes from environment variables (see `.env.example`). `SOBAFM_DISCORD_TOKEN` is required and is removed from the process environment when read, so child processes cannot inherit it; it is excluded from the configuration's representation, and configuration and client errors are logged without values or messages. `SOBAFM_CATALOG` and `SOBAFM_REVIEWS` must be set together; without them `/play` and `/skip` are not registered and a safe warning is logged. With them `SOBAFM_GEMINI_API_KEY` is required. It is removed from the environment in the same way, held only by the matcher and sent only as a request header. `run` closes the matcher after the adapter's shutdown. Each source's state, provided count and admitted count are logged at startup. The entry point below reads this configuration and supplies the decoder-backed producer. Offline tests use faked disnake objects and make no token, gateway or voice contact; they do not establish voice behavior, timing or DAVE negotiation.

## Implemented entry point and deployment

`python -m sobafm` (`__main__.py`) runs in a fixed order. First a limit gate reads the cgroup v2 `memory.max`, `memory.swap.max` and `pids.max` that the process sees at `/sys/fs/cgroup` and refuses to start (exit 3) unless they are exactly ADR 0004's 90177536, 0 and 64. A missing, unreadable or different value refuses before any configuration, catalog, media, Discord or audio input is read. Then the adapter's `Config` reads the token, Gemini key, catalog snapshot and reviews from the environment, and `SOBAFM_MEDIA` names the media manifest, required exactly when a catalog is configured. A configuration error exits 2 without values. Finally the adapter's `run` starts the bot with a `MediaProducer` and handles SIGTERM through the adapter's shutdown.

The catalog snapshot has no audio location, so `media.py` reads a separate bounded operator manifest (at most 256,000 bytes and 1,000 entries, duplicate keys rejected). Each entry binds a recording key to a file relative to the manifest's directory that may not leave it, its exact size and SHA-256, and `max_pcm_bytes`, a whole number of frames up to four hours of PCM that becomes the decode's overrun bound. `MediaProducer` is the adapter's `Producer`: for each track it creates one `DecodeProducer` on the adapter's already-leased bank and runs start, finish and settlement on a worker thread. On cancellation it cancels the decode, keeps awaiting the worker through repeated cancellation, and raises only after the decoder process, its threads and descriptors have actually settled. A failed decode is logged by its failure kind and leaves the bank stopped, so the callback reports a failed switch and current audio continues. The adapter's retirement keeps the single lease, the original three-second clock from the bank's first cancellation, the failed-verdict count and retained debt unchanged.

The `Dockerfile` builds the locked runtime dependencies with uv 0.13.6 on the reviewed Python 3.14 base pinned by digest, then installs the reviewed mpg123 1.33.7 package set with its exact stable dependencies, including libopus, and runs as UID 1000. It contains no FFmpeg. `compose.yaml` defines one service with init, a read-only root, all capabilities dropped, no new privileges, memory and memory-plus-swap 90,177,536 bytes, 64 tasks, two CPUs, `unless-stopped`, a read-only `./data:/data` bind mount and two 1 MB log files. Offline tests check the gate against a fake cgroup root, configuration, the producer with a Python child in place of mpg123, and the deployment files statically. The image build, fit under the group limit, the multi-threaded parent's decoder launch and voice behavior are not yet qualified.
